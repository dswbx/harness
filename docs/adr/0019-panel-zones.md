# Panel zones: docked panels in six zones, laid out by one pure function

The chat had one right panel showing one view at a time, switched by buttons in the Session header, and more panels (Artifacts, Events, left `render_ui` items) were coming. Users want JetBrains-style docking: put the Terminal at the bottom, Changes on the left, both visible at once.

**Six Zones, one Panel each.** left top, left bottom, bottom left, bottom right, right bottom, right top. Each shows one open Panel. The sides split their height when both halves are open; the bottom splits its width only when both bottom Zones are open, otherwise the open one fills it, and it spans the full width under the sides. The chat keeps at least 360 px (the side columns shrink first). Defaults: Changes left top, Artifacts left bottom, Terminal bottom left, Events bottom right, Side chats and `render_ui` items right top (left items: left top). Pure model and geometry (`toggle`, `move`, `reconcile`, `computeRects`, migration) are in `panelLayout.ts` and unit-tested (ADR 0012: Frontend logic, not core).

**Layout per Session.** Zones, which Panel is open, all sizes and the open Side Threads are kept per Session in `localStorage` (`harness.chat.layout.<sessionId>`; the old `harness.chat.panel.<sessionId>` is migrated, `harness.chat.rightPanelWidth` is dropped). The Terminal never comes back open (it would start a shell). "Save as default layout" can come later. A Panel that cannot show (Changes outside a repository, an Artifacts list with nothing in it, a removed `render_ui` item) keeps its place and loses its icon; it returns when it can show again.

**One absolute dock, so moving never remounts.** `DockLayout` measures its box and positions the chat and every mounted Panel absolutely from `computeRects`. All Panels share one parent, so changing a Panel's Zone changes only its rect: the Terminal shell, a half-typed side chat prompt and Events filters survive a move. The Terminal and opened side chats stay mounted while hidden. Resize lines (three sizes, three splits; double-click resets) and the blue drop preview come from the same rects.

**Stripes replace header buttons.** Icons of the left and right Zones sit in two Stripes along the window edges (upper Zone, separator, lower Zone, bottom Zone at the foot). The Session header keeps only the Agent status badge. An empty left Stripe is hidden, and comes back over the edge while a Panel is dragged.

**Pointer-event drag and drop.** From a Stripe icon or a Panel header, after 4 px: a ghost follows the cursor, targets are found with `elementsFromPoint` and `data-drop-zone` / `data-drop-index` (a dashed slot shows the insert index in a Stripe group; pads on the dock edges; a blue rect previews the Panel's new rect), Esc cancels. Not HTML5 DnD: no custom ghost, and the Tauri webview handles file drops itself. A Panel that was open stays open in its new Zone. "Move to" in the Panel menu does the same without dragging.

**Shared Panel chrome.** Every Panel has the same header (`PanelHeader`: title, its own controls, a menu with Expand, Move to and Hide, and a hide button) and the chat's background; the dock draws 1 px lines between areas. Expand is generic (the same element grows to near full-screen with a backdrop, Esc shrinks it); only Events offers it for now.

**Gear menu.** The host Session header has a gear menu at the far right: Settings (the sidebar footer button is gone) and a container the Frontend portals its own entries into, where the chat adds Reset layout. The container exists only while the menu is open, and the Frontend's entries sit outside the menu's React tree, so the host closes the menu on a click on a `data-menu-close` entry (`MenuButton` in `@harness/ui`).
