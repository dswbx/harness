## specta types

`src-tauri/src/api.rs`:

```rust
#[derive(Serialize, Deserialize, Type)]
#[serde(tag = "type")]
pub enum Command { Ping { text: String }, CreateSession { name: String }, Prompt { session_id: String, text: String }, Cancel { session_id: String } }

#[derive(Serialize, Deserialize, Type)]
#[serde(tag = "type")]
pub enum EventKind { SessionCreated { name: String }, MessageChunk { text: String }, ToolCall { id: String, name: String }, Error { message: String }, Heartbeat }

#[derive(Serialize, Deserialize, Type)]
pub struct Event {
    #[specta(type = specta_typescript::Number)]
    pub seq: u64,
    pub session_id: String,
    pub kind: EventKind,
}

pub fn export_ts(path: &str) {
    specta_typescript::Typescript::default()
        .header("// @generated by specta. DO NOT EDIT.\n/* eslint-disable */")
        .export_to(path, &types(), specta_serde::Format)   // Format arg is required in 0.0.14
        .unwrap();
}
// types() = specta::Types::default().register::<Command>().register::<Event>()  (referenced types follow)
```

Generator: `src-tauri/src/bin/gen-ts.rs` -> `cargo run --bin gen-ts` writes `src/generated.ts`. Same function can back a CI drift test (export to string, compare to file).

Output (serde tag respected, clean unions):

```ts
export type Command = { type: "Ping"; text: string } | { type: "CreateSession"; name: string } | ...;
export type Event = { seq: number, session_id: string, kind: EventKind };
export type EventKind = { type: "SessionCreated"; name: string } | ... | { type: "Heartbeat" };
```

Note: serde `tag` applies to unit variants too (`{type:"Heartbeat"}`); doc comments propagate to TS (the `u64` comment leaked onto `Command` since it sat above it).

### u64 / bigint

- specta-typescript 0.0.14 **refuses** `u64/i64/usize/u128...` by default: export panics/errors with `BigIntForbidden` (verified by removing the annotation). It never emits `bigint`.
- Why it matters: serde_json emits u64 as a JSON number, `JSON.parse` yields a JS `number` (lossy > 2^53). A `bigint` type would be a lie at runtime.
- Options: (1) `#[specta(type = specta_typescript::Number)]` per field = explicit opt-in (used; seq will never exceed 2^53); (2) smaller ints; (3) string via `#[serde(with)]` + `#[specta(type = String)]`; (4) `specta_util::Remapper` global remap. Recommend (1) for `seq`/`ts_ms`.
- `serde_json::Value` (result of `execute`) contains bigint types, but only matters if registered in `Types`; the IPC command signatures are not type-collected here (hand-written wrapper `src/api.ts`).
- IPC args like `from_seq: u64` are plain Tauri args (no specta); JS passes `number`.

## IPC (3 commands) - `src-tauri/src/lib.rs`, `src/api.ts`

- `execute(cmd: Command) -> Result<serde_json::Value, String>` (async; JS: `invoke("execute", { cmd })`, Tauri camelCases arg names: `fromSeq`).
- `subscribe(from_seq, channel: Channel<Event>) -> u64`: `tauri::async_runtime::spawn` task sends 1000 events then 1 per 500ms; JoinHandle kept in `Subs` state (HashMap id -> handle).
- `unsubscribe(id)`: aborts task.
- JS: `const ch = new Channel<Event>(); ch.onmessage = fn; invoke("subscribe", { fromSeq: 0, channel: ch })`.

## Results (`bun tauri dev`, debug build)

- Round trip OK: `execute Ping` logged in Rust stderr from both windows; result returned to JS.
- Burst: Rust sends 1000 events in 5-16ms (non-blocking send). JS receives all 1000 in ~20-40ms after subscribe (incl. IPC setup), `outOfOrder=0` in both windows. Channel preserves order (JS side reorders by internal message index).
- Trickle: heartbeat every 500ms arrives; count/last event rendered.
- 2nd window: opened from Rust (`WebviewWindowBuilder::new(&app, "second", WebviewUrl::default())` inside `execute`), loads same frontend, subscribes independently: each got its own subscription id and the full stream.

## Gotchas (runtime)

1. **Leaked subscriptions on webview reload/close**: `channel.send` does NOT return Err when the JS side is gone (HMR reload). Task keeps sending; JS logs `[TAURI] Couldn't find callback id` every message (3000+ lines). Core must tie subscriptions to window lifecycle: key by webview label, abort on `WindowEvent::Destroyed`, and on re-subscribe replace the old one. Frontend: call `unsubscribe` on unmount (done; best-effort only).
2. **React StrictMode** double-mounts effects: first subscription is orphaned unless guarded by a `cancelled` flag (async subscribe resolves after cleanup). Also keep per-subscription counters; sharing a ref between the two produced fake "out of order" (795) counts.
3. `WebviewWindowBuilder` with the same label twice errors ("webview with label `second` already exists"): guard with `get_webview_window`.
4. Building windows from a sync command can deadlock on Windows; the command is `async` here (recommended in Tauri docs).
5. Channel has no backpressure/queue-bound; v1 plan's bounded queue + `Lagged` must be done Rust-side (e.g. mpsc per view feeding the channel).
6. `from_seq` replay semantic here is fake (just numbering start); real replay lives in Session actor.
