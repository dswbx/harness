# Explorations

Notes from explorations. Hints, not facts. They can be out of date. Check them again before you rely on them. Never cite them as the reason for a decision: a decision goes into an ADR ([../adr/](../adr/)), which may link back to the note.

## Format

- One file per topic: `YYYY-MM-DD-<topic>.md`.
- Start with the date and the versions tested (Agents, crates, SDKs).
- **Observed:** what we saw directly (logs, `initialize` responses, test runs).
- **Assumed / unverified:** what we only reasoned out or read in code.
- **Open questions:** what to test next.
